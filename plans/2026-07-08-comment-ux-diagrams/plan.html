One comment entry point + first-class diagrams

Outcome

Two changes to the canvas skill. (1) Comment creation collapses to a single entry point — a Comment mode toggled from the top nav — and every injected per-artifact affordance disappears, so artifacts (especially interactive mockups) render exactly as authored. (2) Diagrams become first-class: a small diagram.js asset renders sequence diagrams and flowcharts from declarative JSON specs, with stable comment anchors on every node and message, chosen per task alongside the existing hand-SVG and div-kit options.

In scope: comments.js/plan.css interaction rework; new assets/diagram.js + node-run tests; reference and template updates. Non-goals: no server changes (serve.py and the comment JSON schema stay byte-compatible); no reviewer-side drawing or diagram editing; no auto-layout engine; no external libraries. See the two other tabs: ux-mockup is a working demo of the proposed mode, diagram-samples shows the exact rendering style with its specs.

The comment UX model

Today there are three ways to start a comment, two of them always armed: a hover 💬 injected into every block (comment-affordance, comments.js:245), a global Alt-click listener (comments.js:264), and the nav's mark picker. The injected button overlaps artifact content, and the global Alt-click steals events from interactive mockups. All three collapse into one:

Decision Comment mode is the only entry point. The nav's mark button becomes Comment (same slot, cmt-nav-btn). Toggled by click or the C key (ignored while typing in inputs). In mode: hover highlights the target (snapping to the nearest data-cmt-id, as the picker does today) — click anchors to the element · Alt-click drops a point pin · selecting text quotes it. Esc or re-click exits.
Decision Mode is sticky. After posting a comment you stay in Comment mode (Figma-style) until Esc — reviews are bursts, and re-arming per comment is the annoying path.
Decision Outside the mode, zero listeners touch the artifact. The mousemove/click/mouseup handlers are no-ops unless the mode is on. Prototype JS in mockup artifacts gets every event; nothing is injected into blocks. Existing display of comments (pins, quote highlights, outlines on commented elements) stays — it's feedback, not an entry point.

What is deleted outright: the injected 💬 button and its CSS (plan.css:170–177, the :hover rule at 71), the global Alt-click listener, and the passive selection capture in openComposer (quotes are captured by the in-mode mouseup instead). The wire format doesn't move: the mode still produces the same componentId / anchor / quote / blockId fields, so old workspaces and old comments replay unchanged.

Try it on the ux-mockup tab — the demo implements exactly this state machine.

Diagrams: declarative specs, deterministic rendering

Hand-authored SVG (shipped in svg-diagrams.md) is right for freeform architecture, but sequence diagrams and flowcharts are geometry-heavy and repetitive — exactly what a tiny renderer should do. A new assets/diagram.js (vanilla, no deps, copied per workspace like the other assets) renders two types from a JSON spec placed in the artifact:

<script type="application/json" data-diagram>
{ "type": "sequence",
  "participants": [
    {"id": "reviewer", "label": "Reviewer"},
    {"id": "server",   "label": "serve.py"} ],
  "messages": [
    {"id": "m-submit", "from": "reviewer", "to": "server",
     "label": "POST /api/approval"},
    {"from": "server", "to": "reviewer",
     "label": "ack digest", "style": "return"} ] }
</script>
L1 auto-mounted: diagram.js replaces the script tag with the rendered SVG at load
L4 participant/node ids are required and become data-cmt-id — reviewers pin comments to lifelines and boxes, and anchors survive edits
L7 a message with an explicit id is also pinnable; omit it and the message renders without an anchor (positional ids would drift on reorder — deliberately not generated)
L10 style: "return" renders dashed — replies/acks read differently from calls
Decision No auto-layout. Sequence order is the y-axis (renderer spaces messages evenly); flowchart nodes declare col/row on a grid and the renderer does boxes, diamonds, orthogonal edges, arrowheads, and labels. Deterministic beats clever — same spec, same pixels, no layout jitter on edit.
Decision Pure-function core. renderDiagram(spec) → SVG string, DOM-free, so it's testable with plain node tests/test_diagram.js (dev-only; runtime still needs nothing but a browser). Styling via the plan.css tokens only.

Which diagram when (this table lands in the reference doc): sequence — actors/services interacting over time (protocols, review loops, auth flows); flowchart — branching logic and processes (algorithms, decision trees, retry policies); hand SVG — freeform architecture and topology; div kit — a quick linear chain. See the diagram-samples tab for both types rendered in the target style, next to their specs.

Scope fence — include / exclude

Must / will
  • Single nav entry point; delete 💬 affordance, global Alt-click, passive selection capture
  • C/Esc keyboard; visible mode state (nav active + crosshair + highlight)
  • Comment JSON schema unchanged; zero serve.py changes
  • diagram.js: sequence + flowchart, token-styled, stable data-cmt-id anchors
  • TDD: tests/test_diagram.js red before implementation
  • Docs/templates updated (tip text, document-quality.md, svg-diagrams.md chooser, SKILL.md review-loop text)
Won't / can't
  • No mermaid / CDN / npm — offline and no-deps are load-bearing
  • No auto-layout graph engine; authors place nodes on a grid
  • No reviewer drawing/editing; review stays comments + answers + approval
  • No animations or decorative styling in diagrams
  • No generated positional anchors (they'd detach on edit — worse than none)
  • Old workspaces keep their copied assets — no migration, by design

Risks & verification

Risk Discoverability regresses. Hover 💬 advertised itself; a nav button doesn't. Mitigations: the panel's empty state and the template tip both say "press C"; plus a one-time subtle pulse on the Comment button until first use (CSS + localStorage flag).
Risk Mode listeners vs prototype JS. In-mode capture handlers preventDefault on artifact clicks — that's the point (comment the button, don't trigger it) — but they must ignore the review UI itself (isOwnUi, already exists) and never leak when mode is off. Verified by the mockup demo + a manual pass.
Risk C collides with an artifact's own key handling. Guard: only bare C (no modifiers), only when the target isn't an input/textarea/contenteditable, and artifacts can opt out with <body data-comment-key="off">.

Verification: node tests red → green for diagram.js; the full Python suite stays green (no server changes); an end-to-end pass on a demo workspace — enter mode, element/pin/quote comment each land with correct fields; mode off → a clickable prototype receives its own events; both sample diagrams render pixel-stable and their nodes take pinned comments.

Open questions

Three genuinely open calls — answer inline; each has a recommended default.

Inside Comment mode, keep Alt-click point pins?

Keep (recommended — pinning an exact spot on a diagram/wireframe is the one thing element anchors can't do; it's now safely gated behind the mode)
Drop — element + quote anchors only; simplest possible model, {x,y} pins die

With the 💬 gone, how should a block show it has open comments?

Small count chip at the block's top-right; clicking it opens the panel at that thread (recommended — it displays existing comments rather than creating new ones, so it doesn't violate the single-entry rule, and jump-to-thread is genuinely useful)
Passive left-edge accent tick only — visible but not clickable; the panel is the only navigation
Nothing on the artifact — the panel and pins/quote-marks are the only signals

Which diagram types should diagram.js ship with?

Sequence + flowchart (recommended — covers interactions-over-time and branching logic, the two geometry-heavy cases; a state-machine type can come later if we feel the need)
Also a state-machine type now (nodes + labelled transitions; flowchart's grid covers most of it, so this may be redundant)
No diagram.js — extend hand-SVG guidance with sequence/flowchart patterns instead (zero new code to maintain, but every sequence diagram is hand-placed geometry)

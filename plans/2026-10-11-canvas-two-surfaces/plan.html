Decisions arrive as a Deck; anything worth looking at (mockups, diagrams, flows) lives on a Board the Deck's option cards deep-link into. Try both tabs first — the questions below assume you have.

1 · What happens to today's five modes?

Replacing is cleaner to explain publicly; keeping modes is less churn in references and muscle memory.

Replace — plan/decide become Deck (plan = gated Deck), mockup/diagram become Board, doc stays
Keep the five modes — Board added as a sixth, plan/decide re-rendered deck-style

2 · Is Claude's pick visible on option cards?

Today's rule hides the lean so "You decide, Claude" stays honest. Showing it is faster but anchors you. The Deck mockup's toggle demos both.

Shown — badge on the card + "accept remaining picks" button
Neutral — options stay unmarked; lean only applied on defer
On demand — hidden until I press a "show leans" control per deck

3 · One decision in focus, or all open at once?

Focus kills the "wall of questions" feel; all-open suits reviewers who skim the whole deck before answering.

Focused — current expanded, answered collapse to ✓ rows, rest dimmed (as mocked)
All open — every card expanded, progress rail still tracks

4 · Board comments: pins at a point?

Pins need a comment-schema extension (x/y + frame id in comments.json) and daemon-served UI; element comments already work everywhere.

Pins — click a spot on a frame, Figma-style (as mocked)
Element comments only — comment on a frame as a whole, no x/y

Settled

Sep-5 "decision-first" spec is absorbed, not pre-implemented

Its components (verdict strip, settled rows, word budgets, meter) become Deck/doc internals in this redesign. Implementing it first would build the document anatomy v2 replaces.

Still zero dependencies — stdlib Python + vanilla JS

Board pan/zoom is ~80 lines of vanilla JS (proven in the mockup). Staying dependency-free keeps the public story ("nothing to install") and the offline guarantee.

Thumbnails start hand-drawn; live Board snapshots later

Deck option cards get Claude-authored mini-wireframes v1; scaled iframe snapshots of Board frames are an upgrade, not a blocker.

Public packaging is a later phase

v2 is designed clean-for-release (no personal paths in assets), but install docs / repo split / naming wait until the tool itself lands.

The ask

Play with both mockup tabs, answer the four questions (defer any), pin/comment what feels wrong, then approve. Approval here green-lights a written spec for the v2 build — no code before that spec is reviewed.

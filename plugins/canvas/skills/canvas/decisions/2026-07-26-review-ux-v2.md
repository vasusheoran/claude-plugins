# 2026-07-26 — Review UX v2: draft-then-send

Status: shipped. Plan + approval: `canvas/canvas-review-ux-v2` in the bastion
workspace (approved 2026-07-26, all four open questions answered).

Decisions that shaped the change, and why:

- **One submission event, not per-comment wakes.** Comments are born
  `pending` (editable, deletable); a single "Send to Claude (N)" posts
  `/api/submit`, which flips the batch to `sent`, records the gate decision,
  and fires one `submission` event. The agent revises once per review pass
  instead of reacting to comments as they land. `/api/approval` still fires a
  legacy `approval` wake so pages loaded with the old widget keep working.
- **Comment state machine over target flags.** `state: pending | sent |
  resolved` replaces `status` + `target: agent|human`. Legacy entries map at
  read time (`open` → sent, `resolved` → resolved); files on disk are never
  rewritten. Private notes were dropped — an unsent draft is the note.
- **Two anchor kinds.** Alt-click point pins removed; element pick (Comment
  mode) and text quote remain. Quoting needs no mode: a selection ≥3 chars
  pops a floating comment bubble (`data-select-comment="off"` opts a page
  out).
- **Neutral options.** Choice questions get synthetic "✎ Other…" (free text,
  `__other__` + `otherText`) and "◇ You decide, Claude" (`__defer__`) rows.
  "(recommended)" suffixes in option text are retired; the argument for a
  default lives in prose. The defer row does not reveal the lean.
- **activity.json + canvas_reply.** Server-appended activity feed (kinds:
  submitted, picked-up, replied, resolved, page-updated, acked) drives the
  bell/toasts/status chips in the chrome. `canvas_reply` lets the agent
  answer a comment in-thread instead of only in chat.
- **One canvas per topic.** Artifact types are per-page metadata
  (`data-canvas-kind` → typed, badged, always-visible tabs), not separate
  canvases — one review state, one gate, one URL.
